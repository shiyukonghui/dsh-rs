# 需求结论 · 中英文点击切换（前端可验证）

## 1. 目标
让「中英文切换」成为**可用功能**：前端有**一键点击**的语言切换入口，点击后 UI
立即按新语言渲染，且偏好持久化（刷新后保持），可通过浏览器点击自动化验证。

## 2. 现状（第一性事实）
- settings ns `locale` = `{preference: "zh"|"en"}`（Applies::Live，D-095 注册）——**存储已就位**。
- `设置编辑 · locale` 卡可保存该值（阶段 7 已浏览器验证写入+乐观锁）。
- **但零消费方**：canvas-shell chrome 全部硬编码中文（111 处 CJK 字面量，其中
  用户可见运行时文案 ≈40 键：header/侧栏/卡生命周期文案/表单动作反馈/聊天/摆位）；
  插件卡内容（标题/列名/emptyText/动作名）来自各单元 ui.json 的**静态中文声明**。
- JS 渲染器时代归档无 i18n 先例（本仓无历史字典可复用）。
→ 本目标的本质＝「有开关无接线」的补全：**给 locale 建消费链 + 点击入口 + 验证面**。

## 3. 自上而下分解
1. **shell i18n 层**：字典模块（key→{zh,en}）+ 语言信号；启动 `settings/describe`
   读 locale.preference（缺省 zh）→ 全壳文案走 `t(key)`。
2. **点击入口**：header「中 / EN」切换钮 → `settings/update`（同 FormSave 形状，
   带 revision）→ 响应成功后切语言信号即时重渲（同 authority：settings 服务端）。
3. **持久化**：写 settings 文档 → 刷新/重开保持；`locale-edit` 卡保存同样驱动
   shell 文案（保存后本页即生效）。
4. **验证**：CDP 浏览器脚本——断言中文文案 → 点 EN → 断言英文文案（含表单
   act 反馈切语言）→ 刷新断言持久 → 点中 → 复原 zh；console 零错。

## 4. 自下而上校验（可行性）
- `settings/describe`/`settings/update` RPC 臂现成（阶段 6/7 实证）；shell 已有
  fetch_rpc 通道。✓
- shell 无路由/无框架级 i18n 依赖——手写小字典（~40 键×2）成本可控、零依赖。✓
- 插件卡内容不在 shell 手里（单元静态声明）→ 边界问题交用户裁决（R1）。
- 多页同时打开的跨页实时同步：不做（点击页即时+刷新即新；跨页广播=过度设计）。

## 5. 边界
做：shell 全 chrome 双语言 + header 切换钮 + 启动读偏好 + 持久化 + 浏览器验证。
不做（除非 R1 选扩）：12 个插件单元 ui.json 文案双语化（需 schema 扩展
title/label 支持 {zh,en} + 单元逐个改造 + 声明面回归，独立立项）。

## 6. 验收标准
1. 点击 header 钮：zh↔en 即时切换（侧栏「全部↔All」、卡载入/动作反馈、聊天
   占位与按钮、重置摆位等肉眼可见），console 零错；
2. 刷新后语言保持（settings 权威）；locale-edit 卡保存 en 同样使 shell 变英文；
3. e2e-audit T0-T17 不劣于基线（语言钮不破坏几何/关闭/板切换）；
4. 验证脚本 + 截图留档 `.spec/locale-toggle/`；DECISIONS 记录。

## 7. 复盘：假设 / 缺信 / 常见错误
- 默认假设：a)「前端」=canvas-shell（60890 画布），非 3080 原版 GUI；
  b) 语言文案范围先 shell chrome（单元内容双语是大工程）；c) 持久化=settings。
- 缺信/待裁决：R1 范围（chrome-only vs 连单元声明）；R2 入口形态（header 钮
  vs 仅卡保存生效）；R3 首次访问是否跟浏览器语言。
- 常见错误：**把字典散进各 rsx 三元表达式**（不可维护）→ 集中字典 + 单一
  t(key)；以及**只切壳不持久**导致刷新弹回——两头都要。

## 8. 用户裁决（已确认 2026-09-06）
- **R1**：连插件卡声明一起双语（ui.json 文案声明双语化，全链落地）。
- **R2**：顶栏「中/EN」一键钮（点击即切+持久化；locale-edit 卡保存同样即时生效）。
- **R3**：默认中文，已存偏好优先。
