## 1. 第一性原理：这件事的根本目的
用户的终态 = 「前端全部由服务单元组成，不再使用 deepseek 前端」。
不可再分的事实：
- 前端能力面已被 13 张服务单元卡全部承载（D-205 终审：TS 全表面取证，
  「不可机械化」清单清空）；双壳审计全绿（s6-audit + t7-closure）。
- 「deepseek 前端」= 根 `/` 的 harness SPA（自带插件图/构建链/维护面）。
- 两者同源后端（同一 RPC 面）——SPA 的存在不是功能必需，是历史路径。
硬约束：SPA 退役**不得**破坏任何现有能力；回滚必须廉价。可取舍：切换节奏、
旧路径保留时长。

## 2. 自上而下：分层目标
- L0 成功标准：浏览器打开根地址即服务单元桌面；SPA 不再被服务。
- L1 子目标：①根路由指向 canvas；②SPA 资产/构建退役；③旧插件图（dsh-api-gateway
  等 SPA 内部件）随之退役。
- L2 验收：根页 13 卡 + e2e-audit 全绿 + 书签/外链无 404 面。

## 3. 自下而上：现有条件校验
- canvas_response 是纯函数路由（D-184 铁律=不回落 SPA）——反向收编只需在
  web.rs 根路由处加一层「根=canvas」决策，不动契约。
- SPA 面（web_root 静态目录 + `__DSH_BOOT__` 注入）在 serve 配置层可摘除。
- 已验证等价物清单：见 D-205；差异项仅 chat 附件/define（D-205 判非目标）。

## 4. 选项与推荐
| 选项 | 动作 | 风险 | 回滚 |
|---|---|---|---|
| A 温和 | `/` → 302 `/canvas`（SPA 保留可达） | 零 | 删重定向 |
| B 直接 | 根直服 canvas，SPA 停服保文件 | 书签外旧深链 404 | 一行配置 |
| C 终局 | 停部署 SPA + 构建链/文档退役 | 不可顺跑 | revert 链 |
**推荐节奏：A →（观察）→ B →（观察）→ C**，每步独立提交。

## 5. 默认假设（用户未明说但默认成立）
- 旧 SPA 深链（如 `/settings` 类前端路由）无人依赖——**需确认**；
- 正式环境 cordis 有 LLM key，chat/审批闭环届时可验（冒烟只到 AUTH 诚实墙）；
- 「不再使用」= 不再服务，不必删源码（删源码另议）。

## 6. 待用户确认的问题（这些答案会改变设计）
1. 根地址期望：canvas 直服（B）还是允许一次跳转（A）？桌面即首页？
2. SPA 旧深链有无外部依赖（文档/书签/自动化）需要 301 兼容表？
3. 退役节奏：三步走还是一次到 C？
4. locale 固定卡裁撤、rows 观感对齐等小尾巴是否与本轮并处理？

## 7. 此类需求最常见的错误
**把「页面消失」当「前端退役」**：SPA 的插件图/构建链/文档若不同步退役，
只是藏起了旧前端而非退役——终态判定必须以「不存在第二前端构建面」为准，
这也是选项 C 独立存在的原因。
