# 需求结论文档 · 用 Semi 设计令牌优化 canvas-shell UI（靠近 DeepSeek Harness 原版）

## 1. 目标
把 canvas-shell（画布壳，端口 60890 的 `/`）的 **视觉表现** 对齐 DeepSeek Harness 原版
（`http://127.0.0.1:3080/`，React + Semi Design，浅色主题）的设计语言：
颜色、字体、圆角、边框、控件质感、表格/标签/气泡样式。逐一检查 13 张插件卡。

## 2. 第一性原理拆解
- **真正目标**：画布界面看起来像原版的「Semi Design 家族」——不是复刻 React 组件，
  而是移植其**设计令牌**（不可再分的事实来源：
  `semi-design-main/semi-design-main/packages/semi-theme-default/scss/`
  = `_palette.scss` 调色板 + `global.scss` 语义色 + 官方 radius/spacing 常量）。
- **硬约束**：①布局几何契约不动（`--gap:10px` D-181 契约、摆位/磁吸/观察器逻辑）；
  ②功能零回归（T0-T17 审计 + 13 卡行为不变）；③样式只在
  `crates/dsh-cli/assets/canvas/canvas.css`（壳内零 CSS——现状即如此，保持）。
- **可取舍假设**：深色主题去留、字体回退栈、卡头信息密度、间距尺度微调。

## 3. 双视角校验
**自上而下（原版应有的样子）**：白底、`rgba(28,31,35,.08)` 发丝边框、
文字 `#1C1F23`/80%/62% 三档、主色 `#0064FA`、primary 浅版背景 Tag、
输入框白底+灰边+6px 圆角、卡片白底浅阴影、Inter/苹方/雅黑字体栈、行高 1.52。
**自下而上（现有条件）**：canvas.css 已全变量化（106 行，:root 8 变量）→
**令牌替换 = 天然低风险改造**；卡 DOM 结构（.card/.cap/.ltable/.srow/.chat-*/
#sidebar/header）不动即可全站生效；Semi 语义色有 light/dark 双块
（dark：bg-0 #16161A / bg-1 #232429 / bg-2 #35363C）→ 双主题皆可行。

**两者冲突点**：无硬冲突。唯一张力=原版浅色 vs 现壳深色 → 交用户裁决（§7 问题 1）。

## 4. skills 与参考利用方式
- `skills/semi-ui-skills/`：面向 React+MCP 组件用法——本改造**不引入 React**，
  取其主题定制指引精神（令牌为准绳），MCP 未配置、无需配置（令牌直接读源码）。
- 原版参考截图：`target/ui-ref/orig-3080.png`（浅色/白卡/发丝线/蓝字主按钮/
  primary 浅版徽章）；现状：`target/ui-ref/curr-60890.png`（深色自造板）。
- 逐卡基线：验证脚本沿用 CDP 截图流（shot-compare.mjs 已就位）。

## 5. 边界（做什么/不做什么）
做：canvas.css 全量令牌化重写（映射表 `--x: var(--semi-*)`）+ 原版细节补齐
（表头浅灰底、Tag 浅版底、focus 蓝圈、按钮 hover/active 三态、气泡浅色化、
字体栈、滚动条细样式、header/侧栏浅色化）。
不做：React 岛/Web Components（上一轮评估=双运行时不划算）；布局结构/交互改动；
3080 那个 GUI 本身（原版是参考，不是改造对象）。

## 6. 验收标准
1. 13 卡 + 空态/表单/列表/聊天/状态五种视图逐一截图，视觉语言=原版家族
   （白底/发丝边/三档文字/蓝主色/浅版 Tag/6px 圆角/字体栈）；
2. 功能零回归：e2e-audit T0-T17 结果不劣于基线、13 卡抽查交互、console 零错误；
3. 布局几何不变：摆位/磁吸/板切换/深链行为与改造前一致；
4. 决策日志（D-224）+ 逐卡对比截图留档 `.spec/ui-semi-tokens/`。

## 7. 复盘：用户假设 / 缺失信息 / 常见错误
- **默认假设**（用户未明说）：a) 原版=3080 浅色界面为基准；b) 只改画布壳不动功能；
  c) 「靠近」=视觉语言对齐而非像素级复刻；d) skills=semi-ui-skills 目录。
- **缺失信息**：主题策略（浅色默认？双主题？）、保真深度（是否含布局微调）、
  原版深色态是否需要（原版 GUI 深色我没截到证据——不能假设存在）。
- **最常犯错误**：逐像素照抄 React 组件 DOM（引入伪组件层）→ 我们只移植**令牌层**，
  DOM 保持 Dioxus 现状；以及改样式时碰坏拖拽/几何契约 → 用审计回归兜底。

## 8. 用户裁决（已确认 2026-09-06）
- **R1 主题策略**：浅色默认 + 保留深色双主题（Semi 官方 dark 令牌 #16161A 系，
  `body[theme-mode="dark"]` 切换）。
- **R2 保真深度**：令牌 + 控件质感层（DOM/布局/几何零改动）。
- **R3 字体栈**：系统栈回退（Inter 优先，不内嵌字体）。

## 9. 首轮实施结果（浅色/深色 + 审计）
- canvas.css 全量令牌化（Semi 调色板三元组 + 语义层 + 深色显式重声明块）；
  双主题截图 `target/ui-ref/new-{light,dark}.png` + 表单卡特写，console 零错。
- **关键坑（D-224 教训）**：`:root` 上以 `var()` 定义的派生变量在 :root 解析后
  **继承固化**——深色块只改三元组不重声明派生变量 = 深色下徽章/active 仍浅色。
  修复=深色块全部显式字面量重声明。
- 功能回归：e2e-audit T0-T17 **与基线逐项一致**（含已知 T5 过时假设 / T7 dom2
  观察项），console 零错——零回归确认。
- 待办（下轮）：逐卡（13 卡 × 五视图）浅色/深色截图逐一检查 + 收尾。
