# 调研结论：Dioxus 与「插件全 Rust 化」——需求分析（2026-09-05）

状态：**调研/待拍板**（未动一行产品代码）。决策落 `docs/DECISIONS.md`（拟 D-210）。

## 0. 现状澄清（调研改变的第一件事）
「插件 Rust 化」这个目标**今天已完成 95%**：13 个装配单元本来就是 Rust 写的
（`wasm-plugins/*/src/lib.rs` → wasip1 组件，跑在服务端 wasmtime 里）。JS 只剩两处：
① 浏览器薄渲染器（core.js+app.js ≈ 1200 行，35 条 node 测试钉死）；② ui.json 声明（数据）。
所以 Dioxus 真正解决的问题**不是「插件不是 Rust」**，而是：
- 渲染器壳的 JS 是否换成 Rust（可测试性/单一语言）；
- **表达力天花板**：form/status/list/chat 四档之外的复杂交互 UI（拖拽、画布、富文本…）。

## 1. Dioxus 体检（依赖引入纪律五维）
| 维度 | 事实（2026-09-05 查证） |
|---|---|
| 维护活跃度 | crates.io max **0.8.0-alpha.1**，正式版 0.7.x，最近发布 2026-07（活跃）[releases](https://github.com/DioxusLabs/dioxus/releases/tag/v0.7.0) |
| 社区采用 | 累计下载 246 万+，近月 88 万+（Rust 前端框架第一梯队） |
| 许可证 | MIT / Apache-2.0 双许可（商用无碍） |
| API 稳定性 | 0.6→0.7 有信号系统级大改；0.8 仍在 alpha——**次版本间有破坏性变更史** |
| 栈契合 | web 目标 = wasm32-**unknown-unknown**（浏览器里跑）+ JS 胶水加载；**不支持 wasip1/组件模型**——与我们的服务端组件运行时**互不兼容，是两个 wasm 世界** |

## 2. 与现行契约的对撞（自上而下 × 自下而上）
| 现行不变量 | Dioxus 化影响 |
|---|---|
| 声明=数据（插件不向浏览器发代码） | 变成发 wasm 代码——本地信任域可接受，但失去「惰性数据」审查面与**无红卡**保证（坏了从红卡变白屏） |
| Rust 零渲染 | 反转——渲染逻辑入 Rust（这正是用户想要的） |
| 13 单元 + 校验/热插拔/rev 全绿 | 校验对代码卡退化；热插拔需内容寻址 wasm 加载（可解，成本在） |
| 多 wasm 模块无共享运行时 | **每单元自带一份 dioxus 运行时**（估 0.7 空壳 wasm 300-800KB/未 gzip）——13 单元 = 体积×13，除非聚合打包（破坏热插拔）或动态链接（unstable）；**spike 必测项** |
| 一页多 Dioxus 应用（岛） | 0.7 支持自定义挂载根，但**多实例并发岛**未见于官方文档明示——**spike 必测项** |
| 服务端自定义 HTTP（非 axum） | dioxus-web 纯客户端不受影响；dioxus **fullstack/SSR 与现服务栈不合**，若用则限定纯 WASM 客户端模式 |

## 3. 选项矩阵（自上而下）
- **A 维持现状**：声明契约继续按 D-nnn 演进。零成本，天花板仍在。
- **B 岛逃生舱（推荐）**：契约新增 `view.kind="island"`——简单卡**照旧声明式**（零迁移），
  复杂单元自愿带 wasm 岛（Dioxus 编写）挂载到卡容器；校验/热插拔/红卡对声明卡原样保留；
  体积代价只落在真需要它的单元。
- **C 壳重写**：桌布壳（侧栏/重排/清单/卡框）用 Dioxus 重写替换 core/app.js，单元仍发声明。
  消灭 JS 渲染器、壳逻辑获得 Rust 测试；13 单元零改动。
- **D 全量 Dioxus 化**：每单元自带 Dioxus app。表达力最大，迁移/体积/保证损失也最大。

## 4. 风险清单（如实）
①0.8-alpha 期 API 漂移（钉 0.7.x 可缓解）；②多岛体积与首屏（spike 数据说话）；
③岛内错误=白屏（需要岛崩溃=红卡的兜底协议）；④双 wasm 世界的心智/工具链成本
（cargo-component vs dx serve 两套）；⑤E2E/测试基建可复用（CDP 不关心谁渲染）。

## 5. Spike 建议（决策前压低不确定性，≤半轮）
用 1 个真单元（候选：聊天——四档之外需求最真实）做岛：测 ①0.7 多实例岛挂载 ②wasm-opt+gzip
实测体积 ③经 `/plugins/<id>/web/` 内容寻址加载 + rev 失效 ④岛崩溃红卡兜底。数据回来再拍板。

## 6. 验收标准（若拍板任一选项）
不劣化现行：13 卡活体绿、E2E 清单全项、热插拔语义；新增：spike 报告（体积/挂载/兜底
实测数字）、D-210 决策条目、新契约字段必须先 live 抓样再造夹具（D-20x 教训）。
