## 1. 目标（第一性）

让**任意服务装配单元**（wasm 插件包）携带的 UI，以一个**独立桌布 GUI 壳**被统一装载与呈现：
插件只声明「一张卡片」的**数据**，桌布负责**分类、排布、渲染、动作回传**。
现有 harness 前端不再是插件 UI 的宿主——它继续承载聊天/会话等成熟资产，而**插件 UI 资产按
「UI + 逻辑」逐块拆成独立服务装配单元**（迁一块、验一块，未迁部分仍用原前端）。

沿用 D-179 三条不变式（本架构不推翻）：**声明是数据不是代码** / **渲染器在浏览器** /
**Rust 只生声明 + 数据面/权限/动作执行，不做渲染**。

## 3. 信息架构

```
┌──────────────── 桌布（GUI 壳，消费声明数据）─────────────────┐
│ ┌───────────┐ ┌──────────────────────────────────────────┐ │
│ │ 左侧固定   │ │ 右侧容器（工作台）                         │ │
│ │ 侧边栏     │ │  10px 网格；卡片按 size 自动流式排布        │ │
│ │           │ │  · 同分类多卡平铺，可滚动                    │ │
│ │ ▸ 分类(type)│ │  · 列数随宽度自适应                        │ │
│ │   (含计数)  │ │  · 点左侧名 → 聚焦/滚动/高亮               │ │
│ │   ▸ 插件名  │ │                                          │ │
│ └───────────┘ └──────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- 侧栏只显示**真正有卡片**的分类（不出空组）；分类下按声明顺序列插件名。
- 侧栏条目来源 = 宿主聚合清单（非前端硬编码），故插件热插后侧栏自动更新。

## 4. 分类枚举 `type`（v1 闭集，面向用户）

`model`（模型/Provider）· `config`（偏好设置）· `capability`（工具/技能）·
`runtime`（jobs/schedule/goal/plan）· `resource`（fs/凭据/工作区）· `session`（会话相关）·
`misc`（兜底：未知 type 落此，保留原值供诊断）

- 加一个分类 = 侧栏多一组，**不需要渲染器**（分类不决定渲染）。
- 未知/缺省 type → 落 `misc`，卡片照常渲染其 view 内容，并保留原始 type 值可诊断。

## 5. 视图枚举 `view.kind`（渲染契约，三档制）

| 档 | 成员 | 要求 |
|---|---|---|
| ✅ v1 实现 | `form`（复用 D-180 字段/动作契约）、`status`（只读键值/指示灯）、`list`（行列表 + 可选行动作） | 渲染器必须画得出；坏声明 fail-loud |
| 🔒 契约预留 | `chat`、`chart`、`table` | 契约签名先定（一步到位，日后不补 schema）；渲染器未建 → **fail-loud 元数据回落**，不白屏 |
| ❌ 否决 | `board` | 它就是画布本身；卡内嵌画布 = 无限递归陷阱。「一行行条目」的需求已由 `list` 覆盖 |

**为什么用三档制**：写进契约的每个 `view.kind` 都等于「渲染器必须画得出」。三档制让
**契约一次定全**（满足用户「一步到位、不留两套并行 schema」），同时**实现按真实需要逐档点亮**，
未点亮档位走已谈定的 fail-loud 回落——不虚报能力，也不产生第二套 schema。

## 6. 排布与坐标

- 网格单位：**10px** 格距（不用打印 pt；pt 依赖 DPI 缩放，屏幕单位不稳）。
- 卡片声明 `size{w,h}`（格数）；**封顶 w≤4 / h≤8**，超出宿主裁剪并记录契约违规。
- **排布顺序 = 声明顺序**（不引入 priority，避免「必须置顶」的隐性扯皮；将来有真实需求再议）。
- 列数 = 由容器宽度推导，**窄屏缩列、宽屏多列**；单卡宽度超可用列数时按可用宽度收。
- 焦点语义：点侧栏插件名 → 画布滚动到该卡并高亮（不改布局、不唯一展示）。

## 7. 发现与热插拔（架构口子，本轮只定契约）

- 宿主端点 `/api/ui-manifest`：返回 `[{ pluginName, cardId, type, title, size, declPath }]` +
  `rev`（代数）。
- **清单必须从实时状态计算**（loader 生效 entries + 包扫描），**不是启动快照**——否则热插不生效。
- 卡身份 = `(pluginName, cardId)`；热拔 → 清单去条目（画布回收网格位）；热插 → 新卡自动入网格。
- 变更通知复用既有 `/plugins/events` SSE（D-175/D-177 HMR 通道），桌布按 `rev` 差量刷新。

## 8. 边界（明确不做）

- **不做**用户拖拽/自由摆放/布局持久化（坐标由画布算，v1 无手动布局）。
- **不做**卡片内嵌套画布（`board` 已否决）。
- **不做** `chat`/`chart`/`table` 渲染器实现（仅契约预留 + 回落）。
- **不推翻** harness 前端；迁移是增量的。
- 沿用试点边界：不做真实 LLM 调用 / 不做 loader entry 依赖激活（`inject`）/ 不做 SSR。

## 9. 验收（层级，供设计/编码阶段细化）

1. **声明=一份契约**：卡片壳 `kind:"card"` 为唯一顶层容器；D-180 顶层 `kind:"form"` 废止
   （迁移后全仓无第二种顶层形态）。
2. 桌布从 `/api/ui-manifest` 出侧栏（按 type 分组 + 计数）+ 右侧按分类平铺卡片，窄/宽屏都无重叠、
   无出界、无空档塌陷。
3. `form`/`status`/`list` 三渲染器端到端可渲染 + 动作回宿主；`chat` 等预留档位落 fail-loud 元数据卡。
4. 未知 type → 落 `misc` 仍可渲染；超 `size` 上限 → 裁剪 + 记录，不崩。
5. 清单 `rev` 变更可被观察（热插拔口子的最小验证；完整热更在后续轮次）。
6. 全回归基线不回归（workspace / clippy / verify-diff / serve 冒烟）。
